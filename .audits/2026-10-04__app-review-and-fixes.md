# Syncly app review and fixes

Date: 2026-10-04

## Scope and evidence

Repository inventory and targeted source review of authentication, onboarding redirects, home/activity/group/plan routes, private-answer collection and recommendation generation, guardian interactions, address inputs, calendar/sharing helpers, chat, themes, mobile layout, and the service worker. Browser checks covered the public landing page, demo, sign-in/reset screens and expired recovery links, including a 390 × 844 viewport.

Skills used: Impeccable audit/harden guidance, accessibility, motion performance, mobile-native, browser/computer-use guidance, and focused security guidance. Impeccable's launcher could not load its local engine; the review used the installed reference instructions and existing PRODUCT.md/DESIGN.md instead.

This is a source and local browser review. Signed-in teen/guardian interactions, actual OAuth/email recovery, device location/push permissions, and live database policies were not exercised. No production data or settings were changed.

## Prioritized follow-up improvements

1. **Make planning updates transactional.** Answer saves, recommendation replacement, selection changes and approvals currently span multiple database requests. Concurrent generation/answer edits can still race. Introduce an input revision and a transactional finalize RPC; invalidate approvals when the approved itinerary changes. Exercise RSVP changes alongside scoring.
2. **Make location-sharing deadlines explicitly timezone aware.** `expiryFor`/`ghostUntilFor` use the server's local calendar for end-of-day and tomorrow-at-6AM choices. Pass the viewer's validated IANA timezone and test DST boundaries before treating these as local-time promises.
3. **Use date-aware venue hours.** `isOpenDuring` handles overnight ranges but does not evaluate weekday/holiday portions of OSM hours. Missing hours also use category assumptions. Show uncertain availability clearly and use a complete parser/provider before promising a venue is open.
4. **Reduce map cost on mobile.** The production Mapbox chunk is approximately 1.87MB before gzip (519KB gzipped). The venue wrapper is lazy but preloads its inner module. Measure when that download occurs and gate preload/map initialization on intent or visibility; retain a useful list while it loads.
5. **Guard delayed reverse-geocoding results.** Search requests ignore canceled results, but selecting an address or requesting device location can still resolve after the user starts typing something else. Use request revisions consistently for selection and location callbacks.
6. **Finish authenticated and hardware QA.** Test guardian approval links, family onboarding, chat scrolling with the phone keyboard, native sharing, location denial/resume, installation and the production service worker across iOS/Android. The local checks cannot establish these outcomes.
7. **Check release configuration.** Carry forward the provider-budget, rate-limit and isolated test-project checks documented in `.audits/2026-09-28__security-audit-and-fixes.md`; this review did not access provider dashboards or change their settings.
